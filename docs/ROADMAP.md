# 开发路线图

阶段按可运行闭环排序。每阶段不得通过手写已有成熟开源组件来绕过复用评估。

## P0：依赖验证与骨架

- 建立 pnpm workspace、Fastify 服务、React UI、SQLite 和 Provider 配置。
- 做 pi-mono、Mem0、MCP SDK 的最小技术验证：Windows 安装、流式对话、压缩触发、记忆本地持久化、工具 schema 往返。
- 形成锁定版本和许可证记录。
- 验收：用户能在 UI 配置 Provider、对话并恢复会话；关键上游依赖在 Windows 可运行。

## P1：Harness 与安全工具

- 接入 pi-mono runtime adapter；保留 provider 路由、预算、取消和事件映射。
- 接入 MCP SDK；实现目录受限文件工具和逐次审批。
- 验收：复用上游上下文压缩；工具越权拒绝、执行可中止且有审计。

## P2：群聊

- 评估并迁移现有 `agent/` 群聊、@ 解析、并行快照和 PASS 机制。
- 增加用户点名、自动协作、最多三轮、打断和 UI 状态。
- 验收：至少三个 Agent 完成协作任务；同轮互不可见后续回复；无死循环和重复刷屏。

## P3：记忆与个人体验

- 集成 Mem0 本地记忆能力；不自写抽取/检索引擎。
- 实现候选审核、来源追踪、编辑、删除和导出；温度/遗忘作为可替换策略。
- 验收：跨会话召回正确；用户可纠错；引擎故障不丢对话或候选。

## P4：插件 SDK 与隔离运行时

- 固定 manifest、TypeScript SDK、JSON-RPC contract 和示例插件。
- 实现子进程监管、权限代理、日志脱敏和崩溃恢复。
- 验收：工具、Agent 模板和工作流均可注册；插件不能越过授权目录或读取密钥。

## P5：Git 插件市场

- 实现安装、插件详情、配置、启停、更新检查、权限差异确认和回滚。
- 验收：示例 Git 插件可完整安装升级和回滚；恶意/不兼容插件无法启用。

## P6：工作流与可靠执行

- 使用成熟工作流/durable 实现完成声明式工作流和 checkpoint；技术选型在 P0 做验证并记录。
- 验收：任务可以暂停、审批后继续、进程重启后恢复；重复执行不会重复产生外部副作用。

## P7：浏览器与发行

- 接入 Playwright 或其 MCP server，使用隔离 profile；完善 Windows 启动与备份。
- 验收：浏览器任务全程可见、敏感提交有审批、应用可从干净 Windows 环境安装运行。

## 后续版本

QQ/AstrBot 渠道、Android 通知事件源、主动性、云端 core + 本地 node、多设备同步和公开插件目录均在 MVP 后立项；保持接口可扩展，不提前实现完整系统。

## 每阶段通用质量门

- 上游版本、许可证、漏洞状态写入 `OSS_REUSE.md`。
- 单元/集成/端到端测试覆盖阶段验收；权限改动另跑越权安全用例。
- 数据格式变更有迁移和备份验证；失败时可恢复。
- README 与用户操作文档同步更新。
