# 插件与安全模型

## 插件范围

首版插件来源为 Git 仓库，支持工具、Agent 模板和声明式工作流。市场 UI 覆盖安装、详情、启停、配置、手动检查更新、锁定版本和回滚；不建设公共托管、评分、计费或开放发布后台。

插件为 Node.js/TypeScript 独立进程，通过 JSON-RPC over stdio 与 Core 通信。Core 向插件提供受控 SDK；插件不得连接 Core 数据库或读取 Core 配置文件。

Manifest 必须声明 `id`, `version`, `entry`, `compatibleCore`, `permissions`，以及可选的 `tools`, `agents`, `workflows`, `configSchema`。安装阶段校验结构、来源、版本和权限；有未知权限或不兼容 Core 版本时拒绝启用。

## 授权与审批

- 默认拒绝。文件访问使用明确的允许目录和读/写分离授权。
- Shell 默认关闭；启用时配置可执行文件白名单、参数约束、超时和输出上限。
- 网络访问按域名声明；浏览器使用独立 profile，不读取用户默认浏览器登录态。
- 删除、发送消息、提交表单等外部副作用要求逐次审批；批准绑定本次工具名和参数摘要。
- 插件不得继承环境变量中的模型密钥；密钥只由 Core Provider adapter 使用。
- 每次调用记录插件、Agent、工具、资源、审批结果和时间；日志对密钥和敏感正文脱敏。
- 停止 Agent 或禁用插件会终止其子进程和未完成调用。

## Git 来源与更新

- 安装支持 Git URL + tag/commit；默认锁定不可变 commit。
- 不执行安装脚本；依赖安装采用冻结 lockfile，并在启用前展示源码来源和所需权限。
- 更新先下载到临时目录、校验 manifest 与权限差异、通过后切换版本；保留上一版本供回滚。
- 初版只安装用户明确指定的仓库，不做后台自动更新。

## 威胁测试

覆盖路径穿越、恶意 manifest、插件越权、环境变量窃取、命令注入、网络越域、进程挂死、资源耗尽、更新供应链篡改和崩溃后残留子进程。任何未授权资源调用必须 fail closed。
